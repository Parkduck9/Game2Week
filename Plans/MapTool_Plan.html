1요구사항 (말씀하신 것 정리)

맵 크기 가변스테이지마다 지정한 가로 × 세로 크기대로 3D 경기장(전투 박스)이 만들어진다. 보석 가변스테이지마다 보석의 개수와 위치를 자유롭게 정한다 (0개 ~ n개). 스테이지 1 ~ n맵은 "스테이지" 단위. 여러 개를 만들어 게임에서 사용한다. JSON은 맵툴로만스테이지 데이터는 JSON으로 저장하되, 사람이 직접 고치지 않고 맵툴에서만 편집한다. 함께 정해진 전투 규칙탄막 턴 중 주인공이 적에게 닿으면 FIGHT/ACT/MERCY, 못 닿으면 ITEM/넘기기. 바닥 평면 8방향 이동, 비스듬한 고정 카메라.

2확인 필요 — 답변 주시면 계획 확정

Q1. 보석은 게임에서 어떤 역할인가요? (가장 중요)

보석의 역할에 따라 데이터 필드와 탄막 턴 규칙이 달라져요.

A탄막 턴 중 주우면 보상 — 예: HP 회복, 다음 공격력 증가, 살려주기 진행도 +1
B적에게 닿기 위한 열쇠 — 보석을 모두(또는 N개) 모아야 적의 보호막이 풀려 닿을 수 있음
C점수 / 재화 — 스테이지 결과에 표시, 나중에 상점 등에 사용
D여러 종류를 섞음 — 보석마다 종류(type)를 지정 (A·B·C 조합)

Q2. 맵툴은 어디서 실행할까요?

AUnity 에디터 창추천 — 메뉴 Tools ▸ Stage Editor. 적 데이터 에셋을 드롭다운으로 고르고, 씬에 실제 3D 경기장 미리보기, "이 스테이지로 플레이" 버튼. Unity가 켜져 있어야 함.
B브라우저 웹 툴 — 지금 대시보드처럼 로컬 서버에서 실행. Unity 없이 편집 가능, three.js 미리보기. 적 목록은 Unity에서 내보낸 목록 파일을 읽어야 함.

Q3. 배치 방식

A격자추천 — 셀 단위(기본 0.5m)로 크기 지정·배치. 편집이 빠르고 검증이 쉬움.
B자유 좌표 — 소수점 위치로 자유 배치 (스냅 옵션).

Q4. 스테이지 진행 방식

A1 → n 순서대로추천 — 결과 화면에서 "다음 스테이지", 마지막 스테이지 후 엔딩/메인.
B스테이지 선택 화면 — 메인에서 원하는 스테이지 고르기.
C둘 다 (클리어한 스테이지만 선택 가능).

Q5. 1차 범위 — 스테이지에 무엇을 넣을까요?

추천 1차 범위: 맵 크기 · 주인공 시작점 · 적 1마리(종류+위치) · 보석 n개 · 사용할 탄막 패턴 목록 · 탄막 턴 시간

2차 후보: 장애물(벽·기둥), 바닥 색/테마, 적 여러 마리, 스테이지별 배경음. 1차에 꼭 넣고 싶은 게 있으면 알려 주세요.

3스테이지 데이터 (JSON) — 제안

파일 구조

Assets/StreamingAssets/Stages/
├─ stages.json          ← 스테이지 순서 목록 (맵툴이 관리)
├─ stage_001.json
├─ stage_002.json
└─ …

스테이지당 파일 하나 → 변경 이력 보기 쉽고, 한 스테이지를 고쳐도 다른 파일에 영향이 없어요.

stage_001.json 예시

{
  "schemaVersion": 1,
  "id": "stage_001",
  "name": "1-1 첫 만남",
  "grid": { "width": 12, "depth": 14, "cellSize": 0.5 },
  "playerStart": { "x": 6, "z": 1 },
  "enemy": { "enemyId": "Enemy_Test", "x": 6, "z": 12 },
  "gems": [
    { "id": "gem_01", "type": "heal",  "x": 3, "z": 6, "spawnChance": 0.25 },
    { "id": "gem_02", "type": "spare", "x": 9, "z": 8, "spawnChance": 0.25 }
  ],
  "gemRules": { "maxPerTurn": 1 },
  "enemyTurn": { "duration": 8.0, "patterns": ["Pattern_Test"] },
  "_tool": { "generatedBy": "StageEditor", "toolVersion": 1, "checksum": "sha256:…" }
}
필드설명
grid.width / depth경기장 크기(셀 수). 실제 크기 = 셀 수 × cellSize m. 예: 12 × 14 × 0.5 = 6m × 7m
playerStart탄막 턴 시작 시 주인공 위치 (셀 좌표)
enemy.enemyId적 데이터 에셋 이름 (EnemyData) — 맵툴은 드롭다운으로만 선택
gems[]보석 위치 목록. 개수 자유. type = heal / attack / spare, spawnChance = 탄막 턴마다 나타날 확률 (0~1)
gemRules.maxPerTurn한 탄막 턴에 동시에 나올 수 있는 최대 보석 수 (기본 1)
enemyTurn탄막 턴 시간과 이 스테이지에서 쓸 패턴 (비우면 적 데이터의 기본 패턴)
_tool.checksum맵툴이 저장할 때 계산. 게임/맵툴이 읽을 때 내용과 안 맞으면 "맵툴 밖에서 수정됨" 경고 → 직접 수정 방지

5기능 목록

1차 (MVP)

  • 스테이지 목록: 추가 · 복제 · 삭제 · 순서 변경
  • 맵 크기 지정 (가로·세로 셀 수, 셀 크기)
  • 격자 위 배치: 주인공 시작점, 적(종류 선택), 보석(개수 자유)
  • 클릭 배치 · 드래그 이동 · 지우개 · 선택 후 속성 편집
  • 실시간 검증 + 오류 위치 강조
  • 저장 (JSON 자동 생성, 체크섬 기록) · 저장 안 한 변경 표시
  • 되돌리기 / 다시 실행

2차

  • 3D 미리보기 (실제 경기장·모델)
  • "이 스테이지로 플레이" — 바로 전투 시작
  • 맵 크기 변경 시 바깥으로 밀려난 배치물 처리 (자르기/당기기 선택)
  • 보석 일괄 배치 (줄·원형·무작위 N개)
  • 장애물, 바닥 테마 (Q5 답에 따라)

6검증 규칙 (저장 전 · 게임 로드 시 둘 다)

  • 맵 크기: 최소 4 × 4 셀, 최대 40 × 40 셀 (범위는 조정 가능)
  • 주인공 시작점·적·보석이 모두 경기장 안
  • 같은 칸에 두 개 이상 겹치지 않음
  • 주인공 시작점과 적 사이 최소 거리 (예: 4셀) — 시작하자마자 닿지 않게
  • enemyId·패턴 이름이 실제 에셋으로 존재
  • 보석 id 중복 없음, 스테이지 id 중복 없음
  • 체크섬 불일치 → "맵툴 밖에서 수정됨" 경고 (게임은 로드하되 개발 빌드에서 경고 표시)

7게임과의 연결

MainMenu ─▶ GameSession.BeginStage(1)
              │
              ▼
  StageRepository ── stages.json + stage_00N.json 읽기 ─▶ StageDefinition (검증 포함)
              │
              ▼
  Battle 씬: BattleArena.Build(stage)   ← 경기장 크기 (가변)
             StageSpawner              ← 주인공 시작점, 적(EnemyData.ViewPrefab), 보석 n개
             탄막 턴                    ← 시간·패턴 = stage.enemyTurn
              │  닿음 → FIGHT/ACT/MERCY   못 닿음 → ITEM/넘기기
              ▼
  Result ─▶ "다음 스테이지" (N+1) / 마지막이면 엔딩·메인
  • 런타임 코드는 JSON 형식을 모르고 StageDefinition(C# 클래스)만 사용 → 형식이 바뀌어도 읽기 코드만 수정
  • AttackPatternData.boxSize(패턴별 박스 크기)는 스테이지 크기로 대체 — 패턴은 경기장 경계를 기준으로 탄을 만든다
  • 읽기·검증·좌표 변환은 순수 C# → EditMode 테스트

8구현 단계

M1. 데이터 & 로더

StageDefinition 클래스, JSON 읽기/쓰기, 체크섬, 검증기, StageRepository(목록·순서). 테스트 스테이지 1개를 코드로 생성.

산출물: Scripts/Stages/*, EditMode 테스트 (검증 규칙별)

M2. 맵툴 1차

스테이지 목록, 크기 지정, 격자 캔버스 배치(시작점·적·보석), 속성 패널, 실시간 검증, 저장, 되돌리기.

산출물: Q2 답에 따라 Editor/StageEditorWindow.cs 또는 Tools/stage-editor.html

M3. 게임 연결

BattleArena.Build(가변 크기 바닥·벽), StageSpawner(주인공·적·보석), 보석 동작(Q1 답), GameSession에 현재 스테이지 번호.

산출물: Battle 씬이 스테이지 JSON으로 구성됨 + PlayMode 테스트

M4. 스테이지 진행

결과 화면 "다음 스테이지", 마지막 스테이지 처리, (Q4 답에 따라) 선택 화면.

M5. 맵툴 2차

3D 미리보기, "이 스테이지로 플레이", 일괄 배치, 크기 변경 시 배치물 처리.
