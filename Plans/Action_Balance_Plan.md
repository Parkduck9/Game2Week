## 0. 최신 사용자 방향 — 허리 카메라 · 색 대응 · 곡선 궤적

2026-10-06 추가 답변을 반영했다. **이 절이 아래 v1의 조작·카메라·제작 순서 제안보다 우선한다.** 마우스 회전+록온, 우클릭 쳐내기, Ctrl 정지 자세, 점프, 8종 궤적과 간격/속도 편집 툴이 사용자 지정 범위이다. 아래 8단계 수치표와 구체 궤적 목록은검증용 제안이며 확정된 패치 값이 아니다. 현재 실제 구현/검증 상태는 1절의 제작 계획과 실제 적용 항목을 따른다.

| 항목 | 사용자 지정 방향 | 남은 결정 |
|---|---|---|
| 전투 흐름 | 피해서 적에게 다가가고 접촉하면 공격·행동 메뉴 | 기존 시간 초과 메뉴 유지 |
| 카메라 | 캐릭터 뒤 허리 높이, 마우스로 회전 + 적 록온 전환 | 록온 키는 마우스 가운데 버튼을 기본안으로 제안 |
| 노랑 | 우클릭 타이밍 쳐내기 / Shift 회피 / 실제 점프 | 탄은 반대쪽 어깨 뒤로 흘려보냄, 타이밍 수치는 검증 |
| 빨강(후속) | Ctrl을 누르고 정지 자세를 취해야 통과 | 자세 전환 시간과 실제 정지 허용 오차는 검증 |
| 파랑(후속) | 움직여야 함 | 실제 속도 기준으로 제안, 임계값은 플레이 검증 |
| 경고 소리 | 공격이 가까워지면 소리가 커짐 | 소리 종류는 임시 자원으로 검증 후 교체 |

| 궤적/툴 | 총 8종, 탄 궤적·발사 간격·속도 변화를 직접 편집 | 8종 목록/툴 세부는 아래 제안, 실제 동작으로 검증 |
| 점프 | 노란 공격을 점프로도 회피 가능하게 제작 | Space 기본안, 높이/공중 시간은 플레이 검증 |
| 조준 | 플레이어 위치에 무작위 오차를 섞은 노란 공격 | 예고 시 목표 고정, 오차 범위·탄 높이 조정 |
| 쳐내기 이동 | 성공 시 탄을 뒤로 튕기며 누르고 있는 방향으로 이동 | 강제 뒤 밀림/이동 정지는 넣지 않는 해석 |

### 색과 궤적을 분리해서 조합

색은 대응 규칙, 그래프는 탄의 이동 경로, 발사원은 공격 방향을 결정한다. 별도 데이터로 둔다. 예: 노랑+직선+정면 → 노랑+사인파+정면 → 노랑+사인파+측면. 이후 빨강/파랑을 배운 뒤 익힌 궤적과 조합한다. 색 세 종류와 새 궤적·측면 공격을 처음부터 동시에 소개하지 않는다.

- 먼저 노랑 공격에 대한 쳐내기/회피/점프 감각을 만든다. 빨강·파랑은 뒤에 확장하고 서로 다른 색을 혼합하기 전에 대응을 따로 소개한다.
- 색 규칙은 충돌 시 DamageResolver가 실제 동작/속도/쳐내기 판정을 읽어 처리한다. 방향키를 누르는 것과 실제 이동은 구분한다. 벽에 막혀 입력만 유지하는 상황은 파랑 대응 성공으로 간주하지 않는 안이다.
- 빨강의 정지 자세가 노랑/파랑까지 막아주는 만능 방어가 되지 않게 한다. 쳐내기의 색별 허용 여부는 노랑 우선으로 설계하고 다른 색에는 임의로 확장하지 않는다.
- 빨강은 Ctrl 정지 자세 + 실제 정지 상태가 둘 다 충족돼야 통과한다. 단순히 이동 입력을 놓은 것은 정지 자세가 아니다. Ctrl을 누르면 이동 명령을 억제하며 대시/공중 중 즉시 자세로 바뀌어 판정을 건너뛰지 않게 한다.
- 노랑은 우클릭 순간의 짧은 판정 구간에서 쳐낼 수 있다. 버튼을 계속 누르는 지속 방어가 아니다. 성공한 탄은 피해를 중복 발생시키지 않고 방향을 바꿔 회수/수명까지 이동한다. 적 반사 피해는 현재 요청에 포함하지 않고 접촉 후 공격 메뉴라는 목표를 유지한다.
- 쳐내기 동안 이동 입력을 계속 받아 입력 방향으로 움직인다. 록온 시 캐릭터가 적을 바라보며 옆/뒤로 이동할 수 있고, 이동 방향과 바라보는 방향을 분리한다. 강제 뒤 밀림은 추가하지 않는다.

### 확정된 쳐내기 동작 — 오른손, 반대쪽 어깨 뒤로

| 탄이 오는 쪽(캐릭터 기준) | 오른손 동작 | 쳐낸 탄의 이동 |
|---|---|---|
| 왼쪽 | 왼쪽에서 오른쪽으로 쳐냄 | 오른쪽 어깨 바깥을 거쳐 등 뒤로 빠짐 |
| 오른쪽 | 오른쪽에서 왼쪽으로 쳐냄 | 왼쪽 어깨 바깥을 거쳐 등 뒤로 빠짐 |

- 화면 좌우가 아니라 캐릭터가 바라보는 방향의 로컬 좌우로 판정한다. 입력에 따른 이동 방향과 공격을 바라보는 방향은 분리한다.
- 쳐내기 순간 탄과 캐릭터의 상대 위치를 캐릭터 right 축에 투영해 진입 측면을 판정한다. 정확히 정면에 들어오는 경우에는 오른쪽 어깨로 보내는 기본안을 두고 애니메이션으로 검증한다.
- 탄을 순간이동시키거나 날아온 길로 단순 반사하지 않는다. 성공 위치 → 반대쪽 어깨 바깥 → 캐릭터 후방으로 이어지는 짧은 곡선을 만든다. 모션과 곡선은 같은 시점에 시작한다.
- 곡선의 기준 좌표는 성공 순간 캐릭터의 위치/방향을 고정한다. 이후 이동/카메라 회전 때문에 탄이 몸을 따라다니지 않는다. 이동 중 오른손과 탄이 자연스럽게 연결되는지 검증하고 View의 손 위치 보정을 사용한다.
- 성공한 탄은 Deflected 상태로 바꾸고 플레이어에 대한 피해 판정을 즉시 끈다. 한 탄에 성공/피해가 같은 프레임에 중복 발생하지 않게 판정 순서를 고정한다. 반대 어깨를 지나는 연출로 다시 자해하지 않는다.
- 성공 후의 잔상/소리/오른손 모션은 왼→오와 오→왼 두 변형을 사용한다. 탄은 수명 또는 경기장 경계에서 회수하고 적에게 반사 피해를 주지는 않는다.
- 누르고 있는 이동 방향은 성공 여부와 무관하게 계속 적용한다. Ctrl 정지 자세/대시/공중 상태 중 동시 쳐내기 허용은 한 맵 시험에서 정리하되, 시작안은 지상 이동 및 점프 중 쳐내기 허용, 대시/정지 자세 중 새 쳐내기 금지로 제안한다.
- 빨강·파랑의 대비 조건을 동시에 강요하는 공격 조합은 금지한다. 전환 유예와 발사 예고로 다음 행동을 읽을 시간을 준다. 겹침 금지는 단순 탄 개수가 아니라 충돌 예상 시간/안전 경로 기준으로 검증한다.
- 색만으로 규칙을 전달하지 않고 모양·효과음·정지/이동 아이콘도 표시한다. 낮은 시점에서의 화면 밖 공격은 소리와 화면 가장자리 방향 표시를 함께 쓴다.

### 그래프 궤적의 초안

총 8종의 궤적 프리셋을 제공하고 진폭/파장/위상/진행 속도·높이를 데이터로 편집하는 안이다. 아래 목록은 제작을 위한 제안이며 공격의 색 규칙과 별개이다.

| 프리셋 | 움직임 | 툴의 주요 조절 값 |
|---|---|---|
| T1 직선 | 목표 방향으로 직진 | 거리·높이·속도 |
| T2 사인파 | 전진하면서 좌우 흔들림 | 진폭·파장·위상 |
| T3 지그재그 | 삼각파로 좌우 방향 교대 | 폭·주기·모서리 완화 |
| T4 포물선 | 날아가며 위로 올랐다 내려감 | 정점 높이·도착 거리 |
| T5 원호 | 한쪽으로 굽는 곡선 | 반경·회전 방향·각도 |
| T6 나선 | 전진 축을 둘러싸고 회전 | 반경·회전 수·축/높이 |
| T7 8자 | 교차하는 루프 경로 | 폭·길이·루프 수·전진량 |
| T8 자유 곡선 | 제어점으로 정의한 경로 | 베지어 제어점·경로 길이 |

`position(t) = origin + forward × speed × t + right × amplitude × sin(2π × frequency × t + phase)`

- forward/right는 발사원 기준의 수평 축. 적 정면/맵 측면 발사원에서 같은 궤적을 재사용한다.
- origin은 발사 순간에 고정한다. 별도 추적형을 만들기 전에는 적/플레이어가 움직인다고 이미 발사한 탄의 기준 좌표가 이동하지 않는다.
- 탄 궤적 그래프와 “탄 여러 발을 사인 모양으로 배치하는 발사 배열”은 별도 기능이다. 이번 툴은 탄 자체의 이동 궤적과 간격/속도 변화가 핵심이며 발사 배열은 추가 설정으로 분리한다.
- frequency가 시간 기준이면 위 식의 speed는 전진 속도이다. 곡선의 실제 속도는 진폭/주파수에 따라 더 빨라질 수 있으므로 속도/곡률 상한을 검증한다. 균일한 실제 속도가 필요하면 호 길이 기반 재매개화를 검토한다.
- 급격히 꺾이는 궤적은 예고/연속 충돌을 고려한다. 곡선 탄의 이전~현재 위치 직선만 검사하면 큰 프레임에서 곡선의 중간이 누락되므로 작은 구간으로 나눠 검증한다.

### 제작 툴 — Unity 패턴 에디터 제안

별도 웹 제작 툴보다 프로젝트 안의 Unity 에디터 창으로 시작하는 안이다. `Tools > Pattern Editor`에서 기존 맵툴과 나란히 사용하며, 변경은 ScriptableObject 에셋으로 저장하고 게임이 같은 평가 코드를 실행한다.

| 화면 | 직접 편집하는 것 |
|---|---|
| 왼쪽 목록 | 패턴 생성·복제·선택, 8종 프리셋 |
| 가운데 3D 미리보기 | 정면/측면 발사원, 목표/캐릭터, 궤적·높이·위험 영역, 허리/전체 시점 전환 |
| 오른쪽 속성 | 노랑/빨강/파랑, 조준 오차, 발사 수/배열, 예고·수명·쳐내기 허용 |
| 아래 그래프 | X/Y/Z 경로, 패턴 시간 기준 발사 간격, 탄 수명 기준 속도 배율 |
| 미리보기 제어 | 재생·정지·한 프레임 진행·시간 스크럽·반복·랜덤 시드 고정 |
| 저장/연결 | 에셋 저장, 검증 오류 표시, ContentCatalog 등록 후 Stage Editor에서 연결 |

- 경로는 정규화된 진행도 u=0~1로 평가한다. 3D 제어점을 가진 베지어 또는 AnimationCurve 기반 좌표로 편집하되 실시간 임의 코드 실행 입력은 필요 없다.
- 탄 속도 그래프는 탄 수명 경과 비율을 입력으로 받는 비음수 배율이다. 물리 단위가 있는 기준 속도에 곱한다. 경로별 호 길이 표를 이용해 거리 진행도를 계산하면 모양 때문에 속도가 무의식적으로 달라지는 것을 줄일 수 있다.
- 발사 간격 그래프는 패턴 경과 시간 기준으로 초 단위를 출력한다. 다음 발사를 예약하는 순간 한 번 평가하고, 발사 시점까지 고정한다. 진행 중 매 프레임 값을 읽어 일정이 흔들리거나 즉시 연속 발사되지 않게 한다.
- 최종 간격은 그래프 값×난이도 배율 후 최소 간격으로 제한한다. 예고·위험 수명·공유 예산도 검증한다. v1 프리팹 배율과 중복 적용하지 않는다.
- 랜덤은 고정 시드로 미리보기/재현이 가능하게 한다. 재생 중 저장한 값과 게임 실행 값이 같은 경로로 평가되도록 미리보기 전용 계산을 만들지 않는다.
- 궤적이 경기장을 떠나거나 캐릭터와 적 사이의 안전 접근로를 막는 경우 경고한다. 프리셋 8종 제공과 최종 맵 밸런스 완료는 별도 완료 기준이다.

### 노랑 조준·점프 회피

- 공격 예고 때 플레이어 위치 + 제한된 무작위 오차를 목표로 정하고 발사 뒤에는 계속 추적하지 않는 안이다. 옆으로 걷기/Shift 회피/점프로 회피할 기회를 보존한다.
- 초기에는 점프로 넘을 수 있는 낮은 탄을 섞어 넣는다. 목표 높이/오차는 에셋에서 정하고 바닥의 예상 통과 지점과 실제 탄 높이를 일치시킨다. 랜덤으로 즉발 피격이나 공중 착지 위치 봉쇄를 만들지 않는다.
- 점프 중에도 실제 몸과 겹친 탄은 맞는다. 노랑의 모든 높이를 자동 무시하는 무적 점프가 아니다. 충분히 높이 올라 낮은 탄을 넘을 때만 회피한다.

### 소리와 허리 높이 카메라

- 사운드는 발사원/위험 탄의 3D 위치에서 재생하고 거리 감쇠로 접근할수록 커지게 한다. 좌우 위치감과 전면/측면 진입 예고를 함께 검증한다.
- 탄마다 큰 루프 소리를 켜지 않는다. 가장 위험한 가까운 공격 소수만 선택하고 전체 음량/동시 재생 수에 상한을 둔다. UI/배경음이 경고를 덮지 않게 믹싱한다. 화면 밖 공격도 충돌 직전에만 알리지 않고 출발 예고를 준다.
- 카메라는 캐릭터 뒤 허리 부근에서 앞을 보는 구도로 검증한다. v1의 30~35도 전체 내려다보기는 최종 목표가 아니다. 캐릭터가 화면을 가리지 않도록 작은 어깨 오프셋과 바닥 예고 가시성을 비교한다.
- 턴 메뉴에는 기존 메뉴 카메라를 사용하고 회피 턴에는 뒤쪽 시점으로 복귀한다. 카메라 벽 충돌/근거리 가림, 빠른 회전 중 입력 방향, 록온 대상이 화면에서 빠지는 상황을 확인한다.

### 답변 후 첫 제작 범위

1. 허리 카메라·마우스 회전/록온·이동·Shift 회피·실제 점프·우클릭 노랑 쳐내기, 한 맵에서 조작 확인.
2. 노랑 직선/사인파 + 플레이어 위치 랜덤 조준, 정면/측면 발사원, 거리 경고음과 화면 밖 표시.
3. 패턴 제작 툴 1차와 총 8종 궤적, 발사 간격/속도 그래프와 같은 런타임 평가 경로.
4. Ctrl 빨강 정지 자세·파랑 실제 이동 판정, 서로 충돌하지 않는 조합.
5. 누적 패턴·발사 간격·공유 예산·8개 맵 연결, 실제 플레이 밸런스.

제작에 필요한 사용자 방향은 정리됐다. 위의 오른손/반대 어깨 쳐내기를 기준으로 제작하며, 나머지 세부 수치는 에셋/툴에서 조정한다. 반사에 의한 적 피해는 추가 요청 전 넣지 않는다. 록온은 가운데 버튼, 점프는 Space라는 기본안을 함께 기록하고 재배치 가능하게 한다.

## 1. 이번 요청과 범위

### 실제 제작 계획 — 사용자 요청으로 1단계 착수

| 단계 | 제작 범위 | 상태 |
|---|---|---|
| 1 | 공통 액션 기반: 허리 카메라·마우스 회전/록온·이동·Shift 회피·Space 점프·우클릭 쳐내기, 1-1 노랑 직선 시험 공격·오른손 모션·어깨 뒤 탄 흘리기 | 구현, EditMode 119 / PlayMode 15 통과 |
| 2 | 노랑 랜덤 조준·사인파·측면 발사원, 접근 경고음·화면 밖 표시 | 구현, EditMode 125 / PlayMode 16 통과 |
| 3 | Unity Pattern Editor, 8종 궤적·발사 간격·속도 그래프·3D 미리보기 | 미구현 |
| 4 | Ctrl 빨강 정지 자세·파랑 이동 판정, 색 학습과 허용 조합 | 미구현 |

1단계의 노랑 직선은 조작 검증용으로 필요하므로 함께 만든다. 초기 수치는 PlayerActionSettings 에셋에 두고 검증 후 조정한다. 1단계에서는 기존 1-2~1-8을 유지했고, 2단계에서는 1-2·1-3의 패턴만 교체한다. 맵 크기·배치·보석·턴 시간은 유지한다. 리깅 없는 현행 모델은 오른손 두 방향 모션을 임시 무기/손 표현으로 확인하고 완성 리깅은 별도 작업이다.

완료 기준: 입력 맵 전환·일시정지·턴 종료에서 액션/커서 복원, 이동 중 쳐내기, 좌우 반대 어깨 뒤 궤적, 점프로 낮은 탄 회피, 대시 무적·쿨다운, 지상 적 접촉 메뉴, EditMode/PlayMode 검증과 실제 화면 확인.

### 실제 적용된 1단계

- PlayerActionSettings 에셋: 이동 3.4m/s, 회피 2m/0.22초·쿨다운 1초·무적 0.08~0.18초, 점프 0.75m/0.65초, 쳐내기 유효 구간 0.04~0.22초·쿨다운 0.55초. 수치는 여전히 조정 가능하다.
- InputReader 경로로 WASD/방향키·Shift·Space·우클릭·휠 클릭·마우스 delta 연결. Player/UI 입력 맵과 ESC 일시정지는 기존 구조 유지.
- 캐릭터 뒤 추적 카메라·마우스 회전·휠 클릭 록온·카메라 기준 이동. 적이 몸에 가리는 문제를 줄이려고 어깨 오프셋 0.70m 적용. 경기장 바깥 카메라 쪽의 장식 경계벽은 숨기며 물리 경계는 유지한다.
- 오른손은 리깅 전 임시 노랑 손 큐와 좌우 쓸기 동작이다. 요청한 완성 캐릭터 손 애니메이션은 아직 아니며, 탄의 반대 어깨→후방 곡선은 실제로 동작한다.
- 1-1은 예고 후 낮은 노랑 직선탄. 높이/상대 이동 판정으로 점프 회피, 대시 무적, 타이밍 쳐내기. 성공 탄은 플레이어 피해 판정 제외.
- 종료 시 지상 위치/액션/탄 정리, 메뉴·일시정지에서 커서 해제/입력 버퍼 정리. 준비 상태/쿨다운과 록온 상태를 화면에 표시한다.
- 1단계 검증: EditMode 119개, PlayMode 15개 통과. 점프·양쪽 쳐내기·이동/록온·일시정지/메뉴·기존 8개 맵/결말 흐름 검증. 초반 카메라 전환 캡처와 완전 전환 후 캡처를 구분하며 실제 입력 체감은 후속 사용자 확인 대상이다.

### 2단계 구체 계획 — 이어서 진행 요청

- 노랑 조준 설정: 목표는 예고 시작 때 플레이어의 바닥 위치에 제한된 랜덤 오차를 더해 고정한다. 난수 시드를 지정해 재현한다.
- 사인파: Bullet의 이동 평가만 교체하고 공통 높이/연속 충돌/쳐내기를 재사용한다. 직선과 사인파를 에셋으로 선택한다. 커브 제작 UI는 3단계이다.
- 측면: 맵 좌/우 경계 안쪽의 발사 지점과 적 발사점을 번갈아 사용하고 진입 방향을 예고한다. 처음 측면 공격은 단독으로 소개한다.
- 소리: 위치를 가진 가까운 탄/경고에 최대 3개 경고 음원을 배정한다. 거리 감쇠·상한을 두며 일시정지/턴 종료에는 멈춘다. 사운드는 교체 가능한 임시 경고 클립으로 시험한다.
- 화면 밖 표시: 카메라에 보이지 않는 가까운 위험/발사원 최대 3개를 HUD 가장자리에 방향과 노랑 기호로 표시한다. 화면 안의 바닥/선 예고와 함께 사용한다.
- 맵 연결: 1-1은 직선 조작 연습 유지, 1-2에 적 발사 사인파, 1-3에 정면/측면 교대 시험 패턴을 연결한다. 기존 맵 배치·보석·턴 시간은 유지한다. 맵 변경은 StageEditorModel로만 저장한다.
- 완료 기준: 랜덤 범위/시드, 사인파 궤적, 측면 예고, 소리 거리 변화와 동시 상한, 화면 밖 표시, 쳐내기 재사용, 일시정지/종료 정리, 기존 흐름 회귀 검증.

### 실제 적용된 2단계 — 검증 완료

| 맵 | 연결 패턴 | 발사 간격 | 예고 시간 | 조준 오차 |
|---|---|---|---|---|
| 1-1 | 적 발사 노랑 직선 | 1.40초 | 0.75초 | 없음 |
| 1-2 | 적 발사 노랑 사인파 | 1.50초 | 0.85초 | 반경 0.25m |
| 1-3 | 적 → 왼쪽 → 오른쪽 교대 노랑 사인파 | 1.65초 | 1.05초 | 반경 0.25m |

- 속도 2.4m/s, 탄 높이 0.32m. 사인파 진폭 0.38m·주파수 0.65Hz. 예고 시 목표 고정, 지정 시드 2718로 조준 오차 재현. 공격은 발사 후 플레이어를 추적하지 않는다.
- 이번 간격은 새 조작과 측면 공격을 배우기 위한 시험 값이라 뒤 맵에서 더 길다. **사용자가 요청한 단계별 간격 감소·패턴 누적 밸런스는 5단계**에서 적용하며 위 시험 값을 최종 패치로 취급하지 않는다.
- 가까운 위험 3개까지 7m 범위 경고음과 노랑 방향 표시. 효과음 설정을 따르며 일시정지/전투 종료에서 정리한다. 경고음은 임시 합성 클립으로 교체 가능하다.
- 화면 밖 가까운 탄/발사원은 HUD 가장자리, 화면 안은 궤적 예고선으로 표시한다. 회피·쳐내기 준비/쿨다운과 자유 시점/록온 상태도 표시한다.
- 탄 충돌은 최대 0.015초 구간으로 나눠 사인파 경로를 검사하고, 각 구간의 플레이어 이전/현재 위치를 보간한다. 캐릭터 판정은 높이 구간과 수평 반경 기반이며 완전한 메시 충돌이 아니다.
- EditMode 125개 / PlayMode 16개 전체 통과. 결과: `Logs/action_phase2_editmode.xml`, `Logs/action_phase2_playmode_retry.xml`. 새 씬 테스트의 InputTestFixture 격리를 기존 입력 테스트와 통일해 첫 전체 실행의 입력 테스트 실패를 해결했다. 8개 맵 생성·입력/일시정지·처치/살려주기/패배·씬 흐름도 재검증했다.
- 실제 화면에서 허리 카메라·적 가시성·측면 예고/표시 확인. 위쪽 표시 캡처에는 화면 밖 투영 검증용 시험 탄이 포함돼 일반 공격과 구분한다. 손 애니메이션·효과음은 임시 자원이다.

사용자 요청: 난이도마다 패턴을 하나씩 늘리고 쏘는 시간을 줄이는 밸런스 패치, 탑다운 느낌을 줄이고 3D 액션처럼 피하는 전투. 초기에는 설계 문서를 작성했고 후속 제작 요청으로 1단계 구현, 이어서 진행 요청으로 2단계 제작까지 진행했다. 코드는 위 실제 적용 항목에 따라 변경했으며 사용자 세이브는 수정하지 않았다.

- 난이도는 우선 기존 8개 스테이지의 진행 단계로 정의한다. 전투가 길어졌다고 무한히 어려워지지는 않는다.
- “쏘는 시간이 줄어듦”은 **발사와 다음 발사 사이의 간격 감소**로 해석한다. 탄막 턴의 제한 시간이나 공격 예고 시간을 같은 비율로 줄이지 않는다.
- 단계마다 새 패턴 1종을 추가해 사용 가능한 패턴 종류를 1 → 8종으로 누적한다. 모든 패턴을 동시에 실행한다는 뜻은 아니다.
- 낮은 추적 카메라 + 카메라 기준 이동 + 짧은 회피 대시 + 점프를 제안한다. 세부 조작과 수치는 구현 전 함께 검토할 초안이다.
- 적에게 접근 → FIGHT/ACT/MERCY, 시간 초과 → ITEM/넘기기라는 기존 턴 구조는 이어간다. 자유 탐험이나 실시간 일반 공격은 이번 범위에 넣지 않는다.

## 3. 8단계 누적 패턴과 발사 간격

| 단계 / 기존 맵 | 새로 배우는 궤적(제안) | 누적 종류 | 기준 발사 간격 | 직선 기준 탄속 | 동시 공격 상한 |

| 2 / 1-2 주황 결정 | T2 사인파 | 2 | 1.25초 | 2.4m/s | 1 |
| 3 / 1-3 좁은 방 | T3 지그재그 | 3 | 1.10초 | 2.5m/s | 1 |
| 4 / 1-4 넓은 들판 | T4 포물선 | 4 | 1.00초 | 2.6m/s | 1 |

위 표는 v3의 궤적 누적 배치 제안이다. 새 궤적 1종을 배울 때 새 색 규칙까지 동시에 추가하지 않는다. 아래 P1~P8은 v1 공격 형태 예시로 유지하며 T1~T8 궤적과 같은 목록이 아니다.

### 간격이 의미하는 것

표는 **기본 원형 공격의 한 묶음과 다음 묶음 사이 간격**이다. 모든 공격을 0.65초마다 반복하는 설정이 아니다. 각 패턴은 초기 반복 간격(baseRepeatInterval)을 가진다.

`repeatInterval = max(pattern.minimumRepeatInterval, pattern.baseRepeatInterval × tier.referenceInterval / 1.40)`

- P1의 baseRepeatInterval=1.40초이면 표의 간격과 같다.
- P2의 한 묶음 내부 연사 간격은 별도 값이다. 외부 반복 간격과 내부 연사 간격에 배율을 중복 적용하지 않는다.
- P4/P5/P7 같은 위험 구역은 예고·활성·회복 시간이 겹치지 않는 최소 반복 간격을 둔다. 예: P7은 예고 1.0초 + 활성 0.3초 + 회복 1.0초라 최소 반복 2.3초.
- 기존 1.1초/0.75초 프리팹에 다시 배율을 곱하지 않는다. 새 에셋에서 기본값을 정리하고 실행 시 한 번만 계산한다.
- 단계 상승의 우선순위는 종류와 발사 간격이다. HP·공격력·턴 시간은 초기 비교에서 그대로 두고, 탄속은 보조적으로만 올린다.

### 발사량과 안전 공간

- P1은 처음에 한 묶음 6발을 기준으로 시험한다. 최종 단계에서도 무조건 10발로 늘리지 않는다.
- 전역 탄 생성 예산은 초안으로 초당 8 → 16발, 살아 있는 탄 24 → 48개 범위. 조합 시 두 패턴이 같은 예산을 공유한다. 위협량은 탄 수 외에 위험 면적·지속 시간도 별도 제한한다.
- 묶음 발사도 예산을 차감하며, 예산 부족 시 묶음 전체를 미룬다. 길어진 deltaTime 때문에 누적 발사를 한 프레임에 몰아 실행하지 않는다.
- 통로 유효 폭은 최소 플레이어 판정 지름 + 양쪽 0.15m 여유. 현재 반지름 0.22m 기준 약 0.74m 이상이며 카메라·이동 변경 후 재측정한다.
- 기존 맵 크기·배치·턴 제한 시간(7~10초)은 우선 유지한다. 특히 좁은 맵은 탄 수/위험 면적을 낮추고 긴 맵은 안전 구간과 접근 가능 시간을 측정한다.

## 4. 패턴별 회피 방식과 예고

| ID | 공격 동작 | 주요 대응 | 공정성 조건 |
|---|---|---|---|
| P1 원형 | 적에서 바깥으로 퍼짐 | 걷기로 빈틈 통과 | 적 주변 탈출 통로, 시작 위치 즉발 금지 |
| P2 조준 | 위치를 고정하고 3발 연사 | 옆 이동 또는 대시 | 조준 선 표시, 발사 이후 추적하지 않음 |
| P3 통로 | 가장자리에서 구멍이 있는 벽 진입 | 통로로 이동 | 진입 방향과 통로 표시, 화면 밖 공격 예고 |
| P4 충격파 | 바닥 가까이 링이 확장 | 점프 또는 링 도착 전 이동 | 낮은 판정 높이와 도착 지점 표시 |
| P5 광선 | 예고한 방향으로 짧은 휩쓸기 | 미리 벗어나기, 타이밍 대시 | 대시 무적보다 위험 접촉 시간이 길면 통과 불가. 이동 회피 경로도 확보 |
| P6 회전 | 빈 구역을 남기는 회전 탄 줄기 | 빈 구역을 따라 이동 | 첫 방향 표시, 양쪽 패턴으로 길 봉쇄 금지 |
| P7 낙하 | 위치 고정 바닥 마커에 공격 | 마커 밖 이동 또는 대시 | 공중도 피격 가능, 점프 만능 회피 금지 |
| P8 교차 | 두 방향의 통로 벽을 엇갈려 보냄 | 순서 읽고 이동/대시 | P3 변형으로 소개, 두 벽의 안전 통로 연결 |

새 패턴 첫 노출은 1.1초 예고, 단독 실행, 한 번의 행동으로 피할 수 있는 배치로 한다. 익힌 공격의 예고는 초안 0.9~0.75초 범위로 유지한다. 빠른 발사 간격과 읽을 수 있는 예고는 별개이다. 형태·바닥 표시·효과음으로 구분하고 색만으로 구분하지 않는다.

## 5. 누적 패턴을 실제로 보여주는 규칙

1. 해당 맵의 첫 턴에는 새 패턴을 먼저 단독으로 보여준다. 첫 발 전 안전 시간 안에 적에게 도달해도 정상 클리어 기회로 인정한다.
2. 새 패턴 시작 전에 접촉으로 종료되었으면 아직 소개하지 않은 것으로 기록하고 다음 턴에 다시 먼저 배치한다. 억지로 턴을 붙잡지 않는다.
3. 이후에는 새 패턴의 비중을 높인 뒤 익힌 패턴 목록을 셔플 백으로 순환한다. 같은 패턴 연속 선택을 피하고, 모두 소진하면 새 순서로 섞는다.
4. 모든 종류를 한 턴에 억지로 넣지 않는다. 늦게 등장하는 패턴은 다음 턴에도 이어서 선택한다. 재도전 시 소개/선택 기록은 초기화한다.
5. 5단계부터 익힌 조합만 최대 2종 허용. 이동 통로가 겹쳐 막히는 조합은 허용 목록에서 제외한다.
6. 종료된 위험이 남아 있으면 다음 패턴을 즉시 겹치지 않는다. “발사 종료”와 “위험 종료”를 따로 다루며, 최종 종료 시 남은 탄과 경고를 모두 정리한다.

조합 허용 예: P1+P2(발사 시간 엇갈림), P6+P7(안전 구역 보존). 초기 제외: P3+P8, P4+P5, 충격파가 진행 중인데 착지 위치 전체에 낙하 마커를 배치하는 조합.

8초 턴 예시(계획용, 실제 맵 턴 길이에 맞춤): 0~1.1초 새 패턴 예고 → 1.1~2.7초 단독 공격 → 2.7~4.7초 익힌 패턴 → 4.7~6.2초 위험 정리/접근 구간 → 6.2~8초 다음 공격. 마지막 0.8초 안에 새 예고를 시작하지 않고 나머지는 접근 시간으로 둔다. 이 시간표는 발사 횟수나 성공을 보장하는 테스트 결과가 아니다.

## 6. 3D 액션 회피 조작 제안

| 항목 | 제안 초안 | 이유 |
|---|---|---|
| 이동 | WASD + 방향키, 3.4m/s부터 검증 | 현재 2.8m/s 대비 접근감 개선, 카메라 기준 바닥 이동 |
| 회피 대시 | Shift, 이동 방향으로 2.0m / 0.22초 | 옆으로 급히 빠지거나 빈틈 통과 |
| 대시 무적 | 시작 후 0.08~0.18초 | 총 0.10초만 무적, 반복 무적으로 해결하지 않음 |
| 대시 쿨다운 | 시작부터 1.0초 | 무한 대시 방지, UI에 준비 상태 표시 |
| 입력 유예 | 0.12초 입력 버퍼 | 종료 직전 입력을 다음 가능한 프레임에 실행 |
| 점프 | Space, 높이 0.75m / 총 0.65초 | 낮은 충격파를 실제 높이로 넘기 |
| 점프 판정 | 점프 자체는 무적 없음, 추가 점프 없음 | 탄/낙하와 실제 몸이 겹치면 공중에서도 맞음 |
| 상태 제약 | 대시 중 점프, 공중 대시 금지(첫 버전) | 조작·판정 조합부터 작게 검증 |
| 확인/취소 | 메뉴에서 기존 Z·Enter / X·Shift 유지 | Player/UI 입력 맵 분리로 Shift 충돌 방지 |

- 대시 입력 시 이동 방향이 없으면 마지막 유효 이동 방향을 사용한다. 벽에 닿으면 실제 이동은 경계에서 멈추며 쿨다운은 소비한다.
- 점프는 모델 장식이 아니라 플레이어 루트의 실제 Y 이동으로 만든다. 지면 위치와 그림자/착지 마커는 분리한다. 임시 모델 단계에서도 자세·잔상·착지 효과로 움직임을 구분한다.
- 낮은 공격과 몸 높이 공격은 실제 위험 높이를 데이터로 정한다. 기존 탄 높이 0.35m를 전부 그대로 두면 점프만으로 해결할 수 있으므로, 높이별 시각 표시와 함께 재조정한다. 실제 몸을 넘은 탄을 공중이라는 이유로 강제로 맞히지는 않는다.
- 대시 무적과 기존 피격 후 1초 무적은 별도 타이머로 관리하고 OR 조건으로 판정한다. 점프는 여기에 포함하지 않는다.
- 적 접촉으로 메뉴를 열 수 있는 조건은 지상 + 대시 종료 상태이다. 대시 중 스쳐 지나가면 즉시 열지 않으며, 종료 시에도 접촉 중이면 열린다. 점프로 적 위를 지나가는 것은 접촉 성공이 아니다.
- 보석은 실제 근처 높이에서만 획득한다. 지상 대시로 줍기는 허용하고 공중에서 바닥 보석을 자동 획득하지 않는다.
- 일시정지에는 이동·쿨다운·무적·공격 예고·일정 모두 멈추고 입력 버퍼를 비운다. 메뉴/턴 종료 시 입력 버퍼와 공격을 정리하며 다음 탄막 턴 시작 때 지상 위치로 초기화한다.

## 7. 카메라와 화면의 3D 느낌

- 기본은 플레이어 뒤쪽에서 비스듬히 보는 **낮은 추적 시점**. 내려다보는 각도 30~35°, FOV 50~55°에서 시작한다. 1인칭/마우스 자유 회전은 첫 버전에서 제외한다.
- 플레이어와 적을 함께 구도에 넣고 이동 방향 앞쪽을 조금 더 보여준다. 시작점~적 거리가 긴 맵은 자동으로 거리를 넓힌다. 위험 구역이 안 보이면 낮은 각도를 고집하지 않고 안전한 전체 샷으로 전환한다.
- 회피 중 yaw를 자동 회전하지 않는다. 카메라 forward/right를 바닥에 투영해 입력 방향을 계산하고 카메라 평활화는 판정에 영향을 주지 않는다.
- 바닥의 약한 격자·그림자·착지 원으로 거리와 높이를 읽게 한다. 캐릭터와 적을 가리는 구조물은 투명 처리하거나 배치에서 제외한다.
- 화면 밖 발사원은 방향 표시와 바닥 진입선으로 알려준다. 위험 경고 영역은 HUD/캐릭터에 가리지 않게 한다.
- 대시 잔상, 점프 자세, 작은 착지 먼지, 적의 준비 동작을 추가한다. 카메라 흔들림은 기존 BattleCameraDirector.Shake를 사용하고 강도 감소/끄기 옵션을 검토한다. 회피 순간 과한 줌/흔들림은 피한다.

## 8. 구현 구조 제안

기존 전투 상태 머신을 유지하고 Player의 이동 상태는 별도 작은 상태 모델로 둔다. 전투 상태는 입력 요청과 접촉 결과만 알고 Transform/카메라를 직접 다루지 않는다.

```text
InputReader (Move / Dodge / Jump)
    ↓ 명령
PlayerMotorModel (Grounded / Dodging / Airborne, 타이머)
    ↓ 이동 결과
PlayerMover + PlayerActionView → 위치·자세·그림자
    ↓ 실제 충돌 정보
BattleWorld / PlayerHitVolume → 탄·위험 구역·적·보석

AttackPatternData → PatternEncounterData → DifficultyProfile
                    ↓
             PatternDirector (선택 / 일정 / 예산)
                    ↓
          IAttackPattern 실행들 + TelegraphView
                    ↓
          BattleEvents → 카메라·이펙트·HUD
```

| 구성(가칭) | 맡는 일 | 데이터의 단일 기준 |
|---|---|---|
| PlayerActionSettings SO | 이동·대시·점프 수치 | 이동 코드 안에 단계별 수치 없음 |
| PlayerMotorModel | 상태 전환·입력 버퍼·시간 | 모델 수치에 맞춰 View가 따라감 |
| PlayerHitVolume | 실제 몸통 캡슐·발 높이·무적 조회 | 외형 바운스와 충돌 높이 혼동 금지 |
| DifficultyProfile SO | 누적 목록·기준 간격·예산·동시 상한 | 단계가 아닌 프로필 에셋을 참조 |
| PatternEncounterData SO | 이번 맵의 새 패턴·조합 허용 목록 | 스테이지 ID별 switch 금지 |
| PatternDirector | 소개 여부·셔플 백·일정·예산 | 한 곳에서 Tick, 시드로 재현 가능 |
| 패턴별 설정/프리팹 | 기본 간격·최소 간격·위험 높이·예고 | 프로필 배율을 한 번만 적용 |

- PatternRunner는 기존처럼 루트 IAttackPattern 하나를 실행한다. 그 루트에 조합 패턴을 연결하고 내부 Director가 하위 패턴을 관리한다. 처음에는 기존 단일 프리팹도 계속 지원한다.
- 소개 여부와 셔플 백은 턴마다 사라지는 프리팹 안에만 저장하지 않는다. BattleController가 전투 동안 유지하는 EncounterProgress를 주입하고 전투 종료 시 버린다. 세이브 저장 대상이 아니다.
- PatternContext에 읽기 전용 플레이어 충돌/행동 정보와 계산된 설정을 주입한다. 하위 패턴이 GameSession이나 씬을 직접 찾지 않게 한다.
- 거리 판정을 일괄 SphereCollider로 바꾸는 것보다, 빠른 탄과 대시는 이전~현재 위치의 상대 이동 구간을 실제 캡슐과 검사하는 연속 판정을 우선 설계한다. 낮은 충격파/광선/낙하는 각각 높이 범위를 가진 위험 볼륨을 사용한다. 경계 밖 회수 전 충돌을 확인한다.
- 점프 중간 궤적은 큰 deltaTime에서 작은 구간으로 나눠 검사한다. 30/60/120fps에서 탄·대시가 서로 통과하는 터널링을 점검한다.
- 한 패턴의 발사가 끝나도 살아 있는 탄은 Director가 관리하며 허용된 정리 시간 뒤 회수한다. 동시 상한은 살아 있는 위험까지 포함한다. End는 하위 패턴·풀·예고·예약을 전부 취소한다.
- 첫 연결은 기존 JSON patterns에 조합 AttackPatternData 이름을 넣는 방식. 변경은 StageEditorModel/StageRepository로만 한다. difficultyId를 JSON에 추가하는 스키마 변경은 첫 버전에서 필요 없다.

## 9. 제작 순서와 각 단계 완료 기준

| 순서 | 만드는 것 | 다음으로 넘어가는 기준 |
|---|---|---|
| A1 | 한 맵에서 낮은 카메라·카메라 기준 이동·대시 | 적/플레이어/접근 길이 보이고, 경계와 무적 타이밍이 일관됨 |
| A2 | 실제 점프·높이 판정·충격파 시험 | 지상에서는 맞고 충분히 높은 공중에서는 피함. 일반 탄/낙하도 실제 몸과 겹치면 공중 피격 |
| A3 | 예고 공통 표시 + P2/P3/P4 | 걷기·대시·점프가 서로 다른 회피 용도로 쓰임 |
| A4 | 누적 프로필·Director·간격/예산 | 새 패턴 우선 소개, 턴을 넘어 진행 유지, 종료/일시정지 정리 |
| A5 | P5~P8 + 8개 맵 연결 | 맵마다 정확히 1종 추가, 1~8종 누적, 간격 단조 감소, 조합 안전성 확인 |
| A6 | 플레이 밸런스·연출·접근 시간 조정 | 실제 사용자의 회피/접근 체감 확인 후 수치 확정 |

먼저 A1~A2를 작은 한 맵에서 만들어 3D 회피 감각부터 확인하는 것을 추천한다. 이 감각이 맞은 뒤 8종 전체 제작과 맵별 밸런스를 진행한다. 리깅 완성이나 새 아트를 기다리지 않고 현재 모델로 먼저 확인할 수 있다.

## 10. 검증과 남은 검토

- EditMode: 대시/점프 전환, 입력 버퍼 소비, 무적 중첩, 상대 이동 충돌, 누적 목록·간격 단조 감소·예산·셔플 백·턴 간 소개 기록.
- PlayMode: 낮은 카메라에서 8개 맵 가시성, 충격파 점프/탄 피격, 지상/공중/대시 적 접촉, 보석, 일시정지·재도전·씬 종료 정리. 실제 Game 창 입력도 별도 확인.
- 플레이 측정: 패턴별 피격 횟수, 회피 사용률, 적 접근 성공률/소요 시간, 화면 밖 피격, 실패 원인을 설명할 수 있는지. 자동 테스트 통과만으로 재미나 최종 밸런스를 확정하지 않는다.
- 초반은 걷기로도 대부분 피하고 후반에는 걷기/대시/점프를 상황에 맞게 쓰도록 조정한다. 점프/대시가 모든 공격을 무시하거나 대시 두 번으로 모든 맵을 통과하면 재조정한다.
- 확정/적용 항목: Shift 회피 + Space 점프 + 우클릭 쳐내기, 허리 카메라/마우스 회전/휠 클릭 록온, 기존 턴 구조. 8종 제작 툴·빨강/파랑·최종 8단계 밸런스는 후속 단계이며 완료로 간주하지 않는다.
