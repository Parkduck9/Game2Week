#사용자가 확인한 문제지금 원인 (코드·데이터 확인)제안 핵심단계
1플레이 시간이 너무 짧다 (20초 안에 끝남)경기장 5~13m, 이동 3.4m/s → 적까지 직선 1.6~4초. 닿으면 바로 턴 끝맵 2~3배 확대 + 전투 목표 시간 (보호막·적 이동은 보류)9

1. 플레이 시간이 너무 짧다

1.1 지금 상태 (측정값)

항목값
경기장 크기12×14칸 ~ 26×12칸, 칸 0.5m → 가로·세로 5~14m
주인공 이동 속도3.4m/s (PlayerActionSettings.moveSpeed)
시작점 → 적 거리1-1 기준 5.5m → 직선 1.6초
탄막 턴 길이8초
적 체력테스트 적 30, 주황 테스트 적 45
측정 봇 결과적에게 닿는 데 1.5~3.8초, 모든 맵 2~3턴에 끝 (Plans/Balance_Report.html)

턴은 "적에게 닿으면 즉시 종료"이므로, 거리가 짧으면 패턴을 거의 보지 못하고 끝난다. 전투 전체도 턴 수가 적어 짧다.

1.2 제안

A. 맵 확대 (필수, 사용자 요청)

  • 시작점 → 적 거리를 18~30m로 (직선 5~9초, 피하면서 10~20초).
  • 방법: 칸 크기 0.5m → 1.0m로 바꾸고 칸 수도 늘린다 (맵툴 한도 40칸 × 2m까지 이미 가능). 스테이지 JSON은 맵툴(또는 맵툴 코드)로만 바꾼다.
  • 맵툴 검증 추가: "시작점-적 최소 거리"를 칸이 아니라 미터로 검사 (기본 15m).
  • 함께 고칠 것:
  • 탄 수명·사거리: 멀리 있는 주인공까지 탄이 닿는지 검사 (패턴마다 수명 × 속도 ≥ 경기장 대각선).
  • 카메라: 넓은 맵에서 적 방향 표시(화면 밖 표시 ✅ 있음)를 더 크게.
  • 보석 배치: 넓어진 맵에 맞게 재배치.

B. 적 보호막 (보류 — 사용자 선택 안 함) — 턴 시작 후 일정 시간 동안 적에게 닿아도 튕겨 나오는 방식. 맵 확대 후 측정 결과가 부족할 때 다시 검토.

C. 적 이동 (보류 — 사용자 선택 안 함) — 맵툴에서 찍은 위치 2~4곳을 적이 옮겨 다니는 방식. 위와 같이 보류.

D. 전투 전체 목표 시간

구간목표 전투 시간목표 턴 수
1-1 ~ 1-21~1.5분4~5턴
1-3 ~ 1-51.5~2.5분5~7턴
1-6 ~ 1-82.5~4분6~8턴

턴 수는 적 체력·FIGHT 피해·자비 조건(3절)으로 맞추고, 측정 봇이 접근 시간 ≥ 6초, 턴 수를 보고서에 표시한다.

1.3 바뀌는 파일 (예상)

  • 스테이지 JSON 8개 (맵툴 코드로 재생성), StageValidator(미터 거리 검사)
  • 패턴 데이터 (사거리 검사), BalanceMeasurementTests, Tools/render_balance_report.mjs (접근 시간·턴 수 표시)

2. 적마다 공격이 하나라 읽기 쉽다

2.1 지금 상태

  • 스테이지 JSON의 enemyTurn.patterns가 Attack_Stage_1-n 하나. 이 안의 PatternDirector가 맵 순서대로 쌓인 패턴(1→8개)을 섞어 쓰긴 한다 🟡.
  • 하지만 새 패턴은 처음 2초 혼자 나오고, 둘째 패턴은 1.6초 뒤에 겹친다. 주인공이 2~4초 만에 적에게 닿으므로 실제로는 패턴 하나만 보고 끝나는 경우가 대부분이다.
  • 두 적(Enemy_Test, Enemy_Test2)이 같은 패턴 묶음을 쓴다 → 적의 개성이 없다.

2.2 제안

A. 적별 기술 세트 (EnemyMoveSet 데이터)

  • 적마다 기술 3~6개. 기술 = 패턴 1개 이상 + 등장 조건(체력 비율, 턴 수, 자비 진행도) + 색(노랑·빨강·파랑).
  • 맵은 "어느 적이 나오는지 + 난이도"만 정하고, 무슨 공격을 할지는 적이 정한다.

B. 동시 사용 = 겹(레이어) 구조

겹역할예
주 공격계속 압박원형 탄막, 사인파
방해이동 경로를 막음빨강 벽(정지해야 통과), 파랑 줄(움직여야 통과)
저격가끔 주인공을 노림 (예고 표시 후)조준 직선탄
맵 장치맵툴로 배치한 발사대고정 회전 포탑
  • 한 턴에 2~3겹이 동시에. 빨강+파랑 동시 금지 규칙(ColorCombinationRules)은 그대로 지킨다.
  • "새 패턴 2초 혼자"는 처음 만나는 기술만 적용하고, 같은 기술의 두 번째부터는 바로 겹친다.

C. 체력 단계 (페이즈) — 체력 70%·35%에서 기술 조합이 바뀌고 발사 간격이 줄어든다. 단계가 바뀔 때 적 대사(6절 대화 시스템)와 짧은 연출.

D. 공격 순서 (콤보) — "원형 탄막 → 1.2초 뒤 저격 3발"처럼 시간표로 묶은 기술. Pattern Editor에 시퀀스 탭을 추가해 시간표를 만든다.

E. 맵 발사 장치 (보류 ❓) — 맵툴에서 경기장 위에 발사대를 놓는 방식. 사용자가 접근 시간 대책으로는 고르지 않았으므로, 넓은 맵에서 "적 근처만 위험"하다고 측정되면 다시 제안한다.

2.3 바뀌는 파일 (예상)

  • 새 데이터: EnemyMoveSet, EnemyMove, AttackSequence (ScriptableObject)
  • PatternDirector/DirectorPlanner (겹·페이즈·처음만 혼자), EnemyData(기술 세트 참조)
  • 맵툴(발사대 배치), Pattern Editor(시퀀스 탭), 스테이지 JSON 스키마 v2 (emitters)

3. 자비가 너무 빠르다

3.1 지금 상태

  • Enemy_Test: 문턱 2, ACT "응원하기"·"말 걸기" 각 +1 → 2턴이면 자비.
  • Enemy_Test2: 문턱 3, "같이 뛰기" +2 → 2턴.
  • 자비 보석(spare)도 진행도를 올린다. FIGHT를 해도 진행도는 그대로.

3.2 제안 — 적마다 "자비 조건" 데이터

공통 규칙 (모든 적, 사용자 결정): FIGHT를 하지 않은 턴이 3번 쌓이고, 그리고 아래 적별 특수 조건을 채워야 자비 가능. FIGHT를 하면 그 카운트가 0이 되는지 / 줄어드는지는 적마다 설정.

적별 특수 조건 (하나 이상, 모두 충족 또는 하나만 충족 선택):

조건 종류예
ACT 순서"칭찬하기 → 같이 뛰기 → 기다리기" 순서대로
탄막 턴 행동쳐내기 5번, 빨강을 정지로 3번 통과, 한 턴 동안 안 맞기
대화 선택대화에서 특정 선택지 고르기 (6절과 연결)
보석자비 보석 2개 모으기
상태적 체력 50% 이하일 때만 (반쯤 지친 뒤 설득)
  • 표시: 적 이름 옆에 "마음" 게이지(또는 단계 아이콘 ○○●). 살펴보기(Check)에서 힌트 문장.
  • 자비 보석: 진행도 직접 증가 → "힌트 1개 공개"로 바꾸는 것을 제안 ❓.
  • 데이터 방식: EnemyData에 SpareRule(조건 목록, [SerializeReference]로 종류별 클래스). 전투 코드에 적별 if 없이 조건 클래스만 추가하면 늘어난다.
  • 이 조건은 전투 상태 머신이 모르는 사건(쳐내기·정지 통과)을 쓰므로 BattleFeedback 구독으로 센다 (이미 사건이 다 있음 ✅).

3.3 바뀌는 파일 (예상)

  • 새 로직: SpareRule, ISpareCondition + 조건 클래스 5종, SpareTracker (순수 C#, EditMode 테스트)
  • EnemyCombatant(CanBeSpared를 규칙으로), EnemyData, 적 에셋 2개, GemRewards(자비 보석), 상태 표시 UI
  • BattleTexts(힌트·게이지 문구)

4. 그래픽 품질 (모델·셰이더·이펙트)

4.1 지금 상태

  • 기본 URP Lit 단색 재질, 후처리(블룸·색 보정) 없음, 그림자·조명 기본값.
  • 이펙트: 피격·보석 임시 파티클, 6단계의 행동 이펙트(회피·쳐내기 등) 🟡.
  • 경기장: 평평한 바닥 + 칸 표시, 배경 없음.

4.2 제안 — "로우폴리를 유지하되 예쁘게" + 모델 교체

로우폴리는 확정된 결정이므로, 폴리곤 수보다 셰이딩·조명·이펙트가 품질을 좌우한다는 방향으로 먼저 끌어올리고, 모델 교체는 출처 결정 후 진행한다.

순서작업내용
11-A렌더 기초후처리 볼륨 (블룸, 색 보정, 비네트, 약한 SSAO), 조명 방향·색, 안개, 하늘(그라디언트)
11-B툰 셰이더Shader Graph 셀 셰이딩(2~3단 명암) + 림 라이트 + 외곽선(렌더러 기능) — 캐릭터·적·소품 공용
11-C탄 셰이더빛나는 탄 + 꼬리(트레일), 색마다 모양 다르게 (노랑 구, 빨강 각진 결정, 파랑 고리) — 색맹 대비
11-D이펙트 세트발사 섬광, 피격 파편, 쳐내기 베기 궤적, 회피 잔상, 정지 자세 붉은 기운, 파랑 통과 속도선, 예고 바닥 표시, 자비·처치 연출
11-E경기장 꾸밈스테이지 테마별 바닥 무늬·가장자리 벽·배경 소품 (맵툴 JSON에 theme 추가)
11-F모델 교체 ❓주인공·적 2종 — 출처 결정 필요 (질문 Q3)
  • 이펙트는 6단계의 BattleFxRig + IBattleFxModule에 모듈만 추가 → 씬 수정 최소.
  • 성능 기준: PC 1080p 60fps (측정 봇으로 프레임 기록 추가).

6. 대화 시스템과 툴 (JSON)

6.1 목표

  • 전투 시작 전, 턴 사이, 체력 단계 전환, 자비 가능, 승리·패배 때 캐릭터가 서서 대화하는 장면.
  • 선택지와 그 결과(자비 진행, 플래그, 다음 대화)를 데이터로.
  • 대화는 JSON + 전용 툴로만 편집 (스테이지 JSON과 같은 규칙).

6.2 JSON 형식 (안)

Assets/StreamingAssets/Dialogues/dlg_stage_001_intro.json

{
  "schemaVersion": 1,
  "id": "dlg_stage_001_intro",
  "speakers": {
    "heroine": { "name": "주인공", "anchor": "player" },
    "enemy":   { "name": "테스트 적", "anchor": "enemy" }
  },
  "start": "n1",
  "nodes": [
    { "id": "n1", "speaker": "enemy", "text": "여기까지 온 거야?", "pose": "talk", "camera": "enemy_close", "next": "n2" },
    { "id": "n2", "speaker": "heroine", "text": "싸우러 온 건 아니야.", "pose": "talk", "camera": "two_shot",
      "choices": [
        { "text": "이야기를 들어 준다", "next": "n3", "effects": [ { "type": "spareCondition", "id": "listened" } ] },
        { "text": "검을 든다", "next": "end", "effects": [ { "type": "flag", "id": "hostile", "value": true } ] }
      ] },
    { "id": "n3", "speaker": "enemy", "text": "...고마워.", "pose": "relief", "next": "end" },
    { "id": "end", "end": true }
  ],
  "_tool": { "generatedBy": "DialogueEditor", "toolVersion": 1, "checksum": "sha256:..." }
}
  • pose → 애니메이션(5절), camera → 카메라 컷 이름(BattleCameraDirector에 등록), effects → 자비 조건(3절)·플래그.
  • 대사 안 짧은 태그(선택): {wait=0.4}, {shake} — 텍스트 속도 설정 ✅ 반영.

연결 — 스테이지 JSON v2

"dialogues": {
  "intro": "dlg_stage_001_intro",
  "phase2": "dlg_stage_001_phase2",
  "spareReady": "dlg_stage_001_spare",
  "victory": "dlg_stage_001_win"
}

적마다 공통 대화는 EnemyData에 같은 방식으로 지정, 스테이지 지정이 있으면 그것이 우선.

6.3 실행 구조

부분역할종류
DialogueDefinition·DialogueJson·DialogueValidator읽기·검증 (끊긴 연결, 없는 화자, 폰트에 없는 글자)순수 C# + EditMode 테스트
DialogueRunner노드 진행, 선택, 효과 적용순수 C# (조건·효과는 등록식, 적별 if 없음)
DialogueState전투 상태 머신의 새 상태 (BattleStateId.Dialogue)상태 클래스
DialogueView대사 상자 + 이름표 + 선택지 (기존 DialogueBox·MenuNavigator 재사용)UI
카메라·자세컷 이름 → 카메라, pose → 애니메이션View

6.4 툴 — Tools ▸ Dialogue Editor

  • 왼쪽: 대화 파일 목록 / 가운데: 노드 목록(또는 연결 그래프) / 오른쪽: 선택한 노드 편집 (화자·대사·자세·카메라·선택지·효과).
  • 저장 시 검증 (연결 끊김, 도달 못 하는 노드, 정적 폰트에 없는 글자) — 실패하면 저장 안 함.
  • "미리 보기": 툴 안에서 대화를 한 줄씩 넘겨 보기. "바로 플레이": 해당 스테이지로 전투 시작 (맵툴 M5 방식 재사용).
  • 맵툴에서 스테이지마다 대화 파일을 고르는 칸 추가.

6.5 주의

  • 폰트가 정적 아틀라스라 새 대사의 한글이 없으면 □로 나온다 → 툴 검증 + FontCoverageTests가 대화 JSON까지 검사. 없는 글자가 나오면 아틀라스 재생성 단계(문서화)를 안내.
